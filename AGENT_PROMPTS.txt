PROMPT FOR CODING AGENT
═══════════════════════════════════════════════════════════════════════════════

Transform GhostTrace from a standalone application into a user-friendly npm package that can be easily integrated into any Node.js/Express backend.

**Read and implement everything in:** `/home/wal8y/Desktop/graduation/CODING_AGENT_PROMPT.md`

**Core Goal:** Enable developers to:
1. Install: `npm install ghosttrace`
2. Initialize in their app: `await ghosttrace.init({ adminEmail: '...', adminPassword: '...' })`
3. Secure routes: `app.use('/api', ghosttrace.secure())`
4. Access dashboard: `http://localhost:3001`

**Key Requirements:**

1. **Create Main Entry Point** (`index.js`):
   - Export `init()` function
   - Export `secure()` middleware factory
   - Export version

2. **Create lib/ Directory** with:
   - `lib/init.js` - Initialization (setup DB, admin, dashboard server)
   - `lib/middleware.js` - Middleware factory (secure function)
   - `lib/dashboard-server.js` - Separate Express server for dashboard
   - `lib/config.js` - Configuration management with validation
   - `lib/setup-admin.js` - Admin user creation with bcrypt

3. **Environment Variables** (all prefixed with GHOST_):
   - GHOST_ADMIN_EMAIL (required)
   - GHOST_ADMIN_PASS (required)
   - GHOST_PORT (dashboard port, default 3001)
   - GHOST_PROXY (proxy port, default 3002)
   - GHOST_BLOCK_THRESHOLD (default 70)
   - GHOST_RATE_LIMIT (default 120)
   - GHOST_BLOCK_ON_THREAT (default true)
   - GHOST_DB_* (database config)

4. **Database Auto-Setup**:
   - Auto-create database if it doesn't exist
   - Run migrations automatically
   - Fallback to SQLite if no DB configured
   - No manual setup required by user

5. **Admin User Setup**:
   - Created automatically on first init
   - Updated if credentials change
   - Password hashed with bcrypt
   - Must provide clear error if credentials missing

6. **Dashboard Separation**:
   - Runs on separate port (GHOST_PORT)
   - Includes all existing SOC/MDR routes
   - Serves static UI files
   - Independent from user's main app

7. **Examples** (create in examples/ directory):
   - `express-basic.js` - Minimal example
   - `express-social-media.js` - Social media backend example
   - `express-ecommerce.js` - E-commerce backend example

8. **Documentation**:
   - Update README.md with integration focus
   - Create .env.example with GHOST_ variables
   - Add TypeScript definitions (index.d.ts) if possible

9. **Backward Compatibility**:
   - Keep existing server.js working as standalone mode
   - Don't break existing API
   - Existing deployments must continue working

10. **Error Handling**:
    - Clear error if admin credentials missing
    - Graceful fallback if database fails
    - Port conflict handling
    - Helpful error messages

**Implementation Checklist** (mark each when complete):
□ Create index.js
□ Create lib/init.js
□ Create lib/middleware.js
□ Create lib/dashboard-server.js
□ Create lib/config.js

□ Create examples/express-ecommerce.js
□ Update README.md
□ Create .env.example with GHOST_ vars
□ Test with sample Express app
□ Verify backward compatibility
□ Add TypeScript definitions

**Success Criteria:**
- Integration takes < 10 lines of code
- Works with zero manual database setup
- Dashboard accessible immediately after init
- Admin login works with provided credentials
- All existing features continue working

**Important:** Follow the detailed specifications in CODING_AGENT_PROMPT.md exactly. Every function, parameter, and behavior is specified there.
